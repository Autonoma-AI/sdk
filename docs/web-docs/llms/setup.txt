# Setup Guide

## Prerequisites

- A backend with **Prisma** or **Drizzle** and a generated client
- **PostgreSQL**, **MySQL**, or **SQLite**
- Node.js 18+

## 1. Install

Pick the packages that match your stack:

**Next.js App Router + Prisma** (most common):
```bash
pnpm add @autonoma/sdk @autonoma/sdk-prisma @autonoma/server-web
```

**Express + Prisma**:
```bash
pnpm add @autonoma/sdk @autonoma/sdk-prisma @autonoma/server-express
```

**Hono / Bun / Deno + Drizzle**:
```bash
pnpm add @autonoma/sdk @autonoma/sdk-drizzle @autonoma/server-web
```

**Node.js http + Prisma**:
```bash
pnpm add @autonoma/sdk @autonoma/sdk-prisma @autonoma/server-node
```

### Package reference

| Your ORM | Package |
|----------|---------|
| Prisma | `@autonoma/sdk-prisma` |
| Drizzle | `@autonoma/sdk-drizzle` |

| Your Framework | Package |
|----------------|---------|
| Next.js App Router, Hono, Bun, Deno | `@autonoma/server-web` |
| Express, Fastify | `@autonoma/server-express` |
| Node.js http | `@autonoma/server-node` |

## 2. Find your scope field

Open your Prisma schema (or Drizzle schema). Look for the FK that most models use to reference a root entity:

```prisma
model User {
  organizationId String
  organization   Organization @relation(fields: [organizationId], references: [id])
}

model Application {
  organizationId String
  organization   Organization @relation(fields: [organizationId], references: [id])
}

model Member {
  organizationId String
  organization   Organization @relation(fields: [organizationId], references: [id])
}
```

If most models have `organizationId` (or `orgId`, `tenantId`, `workspaceId`), that's your scope field.

**Important**: The scope root model (usually `Organization`) does NOT have this field on itself. The SDK knows this — it reads the FK graph and only injects the scope field into models that have it as a column.

## 3. Generate secrets

You need two **different** secrets. The SDK will throw an error at startup if they are the same.

```bash
openssl rand -hex 32   # → use as AUTONOMA_SHARED_SECRET
openssl rand -hex 32   # → use as AUTONOMA_SIGNING_SECRET (must be different!)
```

Add to `.env`:

```env
AUTONOMA_SHARED_SECRET=abc123...   # share this with Autonoma
AUTONOMA_SIGNING_SECRET=def456...  # keep this private, never share
```

If you have `.env.example`, add placeholders there too:

```env
AUTONOMA_SHARED_SECRET=
AUTONOMA_SIGNING_SECRET=
```

## 4. Create the endpoint

### Next.js App Router

```typescript
// app/api/autonoma/route.ts
import { createHandler } from '@autonoma/server-web'
import { prismaAdapter } from '@autonoma/sdk-prisma'
import { prisma } from '@/lib/db'

export const POST = createHandler({
  adapter: prismaAdapter(prisma, { scopeField: 'organizationId' }),
  sharedSecret: process.env.AUTONOMA_SHARED_SECRET!,
  signingSecret: process.env.AUTONOMA_SIGNING_SECRET!,
  auth: async (user) => {
    // Create a real session for this user — see section 5
    const session = await createSession(user.id as string)
    return {
      token: session.token,
      cookies: [{ name: 'session', value: session.token, httpOnly: true, sameSite: 'lax', path: '/' }],
    }
  },
})
```

### Express

```typescript
// routes/autonoma.ts
import { createExpressHandler } from '@autonoma/server-express'
import { prismaAdapter } from '@autonoma/sdk-prisma'
import { prisma } from '../db'

app.post('/api/autonoma', createExpressHandler({
  adapter: prismaAdapter(prisma, { scopeField: 'organizationId' }),
  sharedSecret: process.env.AUTONOMA_SHARED_SECRET!,
  signingSecret: process.env.AUTONOMA_SIGNING_SECRET!,
  auth: async (user) => {
    const token = jwt.sign({ sub: user.id }, process.env.JWT_SECRET!)
    return { token }
  },
}))
```

### Hono

```typescript
// src/routes/autonoma.ts
import { createHandler } from '@autonoma/server-web'
import { prismaAdapter } from '@autonoma/sdk-prisma'
import { prisma } from '../db'

const handler = createHandler({
  adapter: prismaAdapter(prisma, { scopeField: 'organizationId' }),
  sharedSecret: process.env.AUTONOMA_SHARED_SECRET!,
  signingSecret: process.env.AUTONOMA_SIGNING_SECRET!,
  auth: async (user) => {
    const token = await createToken(user.id as string)
    return { token }
  },
})

app.post('/api/autonoma', (c) => handler(c.req.raw))
```

### Drizzle + Express

```typescript
import { createExpressHandler } from '@autonoma/server-express'
import { drizzleAdapter } from '@autonoma/sdk-drizzle'
import { db } from '../db'
import * as schema from '../db/schema'

app.post('/api/autonoma', createExpressHandler({
  adapter: drizzleAdapter(db, schema, { scopeField: 'organizationId' }),
  sharedSecret: process.env.AUTONOMA_SHARED_SECRET!,
  signingSecret: process.env.AUTONOMA_SIGNING_SECRET!,
  auth: async (user) => {
    const token = jwt.sign({ sub: user.id }, process.env.JWT_SECRET!)
    return { token }
  },
}))
```

### Node.js http

```typescript
import { createNodeHandler } from '@autonoma/server-node'
import { prismaAdapter } from '@autonoma/sdk-prisma'
import { prisma } from './db'

const handler = createNodeHandler({
  adapter: prismaAdapter(prisma, { scopeField: 'organizationId' }),
  sharedSecret: process.env.AUTONOMA_SHARED_SECRET!,
  signingSecret: process.env.AUTONOMA_SIGNING_SECRET!,
  auth: async (user) => ({ token: 'test-token' }),
})

http.createServer((req, res) => {
  if (req.method === 'POST' && req.url === '/api/autonoma') {
    return handler(req, res)
  }
  res.writeHead(404).end()
}).listen(3000)
```

## 5. Implement the auth callback

The `auth` callback receives the first `User` record created during the `up` action. It must return real, working credentials that the test runner can use to log in to your app.

**This is critical.** If the auth callback returns fake or expired tokens, every single test will fail at the login step. The callback must create credentials using the same auth mechanism your real app uses.

### What the callback receives

The callback receives the full User record as created in the database:

```typescript
auth: async (user) => {
  // user is the first User record from the scenario, e.g.:
  // { id: 'clxyz...', name: 'Admin', email: 'admin-abc123@test.com', ... }
}
```

### What the callback must return

Return an object with one or more credential types:

```typescript
interface AuthResult {
  token?: string                    // Bearer token
  cookies?: Array<{                 // Session cookies
    name: string
    value: string
    httpOnly?: boolean
    sameSite?: string
    path?: string
  }>
  headers?: Record<string, string>  // Custom auth headers
  credentials?: {                   // Email/password for manual login
    email: string
    password: string
  }
}
```

### Pattern 1: Session cookies (most web apps)

Look at how your app creates sessions. Search your codebase for `createSession`, `lucia`, `better-auth`, `iron-session`, or similar.

```typescript
auth: async (user) => {
  // Use your app's real session creation
  const session = await lucia.createSession(user.id as string, {})
  const cookie = lucia.createSessionCookie(session.id)
  return {
    token: session.id,
    cookies: [{
      name: cookie.name,
      value: cookie.value,
      httpOnly: true,
      sameSite: 'lax',
      path: '/',
    }],
  }
}
```

### Pattern 2: JWT bearer token (APIs, SPAs)

Search your codebase for `jwt.sign`, `jose`, `jsonwebtoken`.

```typescript
auth: async (user) => {
  const token = jwt.sign(
    { sub: user.id, email: user.email },
    process.env.JWT_SECRET!,
    { expiresIn: '1h' }
  )
  return { token }
}
```

### Pattern 3: Email/password (mobile apps)

When the test runner needs to log in through the UI (e.g., mobile apps), return credentials instead of a token. The runner will type them into the login form.

```typescript
auth: async (user) => ({
  credentials: {
    email: user.email as string,
    password: 'test-password-123',
  },
})
```

**Important**: For this to work, the User must be created with a password hash in the scenario data. Set the password field explicitly in your scenario:

```json
{
  "create": {
    "Organization": [{
      "name": "Test Org",
      "members": [{
        "role": "owner",
        "user": [{
          "email": "admin-{{testRunId}}@test.com",
          "name": "Admin",
          "passwordHash": "$2b$10$..."
        }]
      }]
    }]
  }
}
```

### Pattern 4: Custom auth headers

```typescript
auth: async (user) => ({
  token: apiKey,
  headers: {
    'X-API-Key': apiKey,
    'X-User-ID': user.id as string,
  },
})
```

### Common mistakes

| Mistake | What happens | Fix |
|---------|-------------|-----|
| Returning a hardcoded string like `"test-token"` | Every test fails at login | Use your real session/JWT creation |
| Not setting password on the User record | Email/password login fails | Add password hash in scenario data |
| Token expires too quickly | Tests fail midway | Set expiration to at least 1 hour |
| Wrong cookie name | Browser doesn't send the cookie | Check your app's cookie name in DevTools |

## 6. Verify

### Smoke test with curl

```bash
SECRET="your-shared-secret-here"
URL="http://localhost:3000/api/autonoma"
BODY='{"action":"discover"}'
SIG=$(echo -n "$BODY" | openssl dgst -sha256 -hmac "$SECRET" | sed 's/.*= //')
curl -s -X POST "$URL" \
  -H "Content-Type: application/json" \
  -H "x-signature: $SIG" \
  -d "$BODY" | jq .
```

**Expected**: A JSON response with your full schema — models, fields, edges, relations. If you see this, your endpoint is working.

**If you get 404**: You're running in production mode. Set `NODE_ENV=development` or add `allowProduction: true` to the config.

**If you get 401**: The HMAC signature doesn't match. Make sure `SECRET` matches your `AUTONOMA_SHARED_SECRET` exactly.

### Integration test with checkScenario

Install test dependencies:

```bash
pnpm add -D vitest testcontainers @testcontainers/postgresql
```

```typescript
// tests/autonoma.test.ts
import { describe, it, expect, beforeAll, afterAll } from 'vitest'
import { PostgreSqlContainer } from '@testcontainers/postgresql'
import { PrismaClient } from '@prisma/client'
import { prismaAdapter } from '@autonoma/sdk-prisma'
import { checkScenario } from '@autonoma/sdk'
import { execSync } from 'node:child_process'

describe('environment factory', () => {
  let container, prisma, adapter

  beforeAll(async () => {
    // Start a real Postgres in Docker (requires Docker running)
    container = await new PostgreSqlContainer('postgres:16-alpine').start()

    // Push your schema to the test database
    execSync('npx prisma db push --skip-generate --accept-data-loss', {
      env: { ...process.env, DATABASE_URL: container.getConnectionUri() },
      stdio: 'pipe',
    })

    prisma = new PrismaClient({ datasourceUrl: container.getConnectionUri() })
    adapter = prismaAdapter(prisma, { scopeField: 'organizationId' })
  }, 60_000) // 60s timeout — container startup takes time

  afterAll(async () => {
    await prisma.$disconnect()
    await container.stop()
  })

  it('empty scenario — org + user only', async () => {
    const result = await checkScenario(adapter, {
      create: {
        Organization: [{
          name: 'Test Org [{{testRunId}}]',
          slug: 'test-{{testRunId}}',
          members: [{
            role: 'owner',
            user: [{ email: 'admin-{{testRunId}}@test.com', name: 'Admin' }],
          }],
        }],
      },
    })

    expect(result.valid).toBe(true)
    expect(result.phase).toBe('ok')
    // result.timing.upMs / result.timing.downMs show performance
  })

  it('standard scenario — org with apps, tests, runs', async () => {
    const result = await checkScenario(adapter, {
      create: {
        Organization: [{
          name: 'Acme [{{testRunId}}]',
          slug: 'acme-{{testRunId}}',
          members: [
            { role: 'owner', user: [{ name: 'Alice', email: 'alice-{{testRunId}}@test.com' }] },
            { role: 'admin', user: [{ name: 'Bob', email: 'bob-{{testRunId}}@test.com' }] },
          ],
          applications: [{
            _alias: 'webApp',
            name: 'Marketing Website',
            architecture: 'WEB',
            webApplicationData: [{ url: 'https://acme.com' }],
            tags: [
              { name: 'Critical', color: '#DC2626' },
              { name: 'Flaky', color: '#EAB308' },
            ],
            testPlans: [{
              name: 'Smoke Plan',
              plan: 'Basic smoke tests',
              testGenerations: [{
                _alias: 'gen1',
                conversation: '[]',
                status: 'success',
                applicationId: { _ref: 'webApp' },
              }],
            }],
            tests: [{
              name: 'Homepage Test',
              testGenerationId: { _ref: 'gen1' },
              steps: [
                { order: 1, interaction: 'click', params: {} },
                { order: 2, interaction: 'assert', params: {} },
              ],
              runs: [{}, {}, {}],
            }],
          }],
        }],
      },
    })

    expect(result.valid).toBe(true)
  })

  it('large scenario — 10k runs with batch insert', async () => {
    const result = await checkScenario(adapter, {
      create: {
        Organization: [{
          name: 'Heavy [{{testRunId}}]',
          slug: 'heavy-{{testRunId}}',
          members: [{ role: 'owner', user: [{ name: 'User', email: 'heavy-{{testRunId}}@test.com' }] }],
          applications: [{
            _alias: 'app',
            name: 'App',
            architecture: 'WEB',
            testPlans: [{
              name: 'Plan',
              plan: 'x',
              testGenerations: [{
                _alias: 'gen1',
                conversation: '[]',
                applicationId: { _ref: 'app' },
              }],
            }],
            tests: [{
              name: 'Test',
              testGenerationId: { _ref: 'gen1' },
              runs: [{ _count: 10000, _batch: true }],
            }],
          }],
        }],
      },
    })

    expect(result.valid).toBe(true)
    expect(result.timing.upMs).toBeLessThan(5000) // batch insert should be fast
  })
})
```

Run it:

```bash
npx vitest run tests/autonoma.test.ts
```

### What checkScenario does

`checkScenario` runs the full `up` → `down` cycle against a real database. It:
1. Creates all entities from your scenario
2. Tears down all created data
3. Returns structured results

```typescript
const result = await checkScenario(adapter, scenario)

result.valid   // true if everything worked
result.phase   // 'ok' | 'up' | 'down' — where it failed
result.errors  // array of { phase, message, fix? }
result.timing  // { upMs, downMs } — performance numbers
```

If it fails, `result.errors[0].fix` tells you exactly what to change. See the Validation page for all error types and fixes.

## 7. Enable in production

The endpoint returns 404 in production (`NODE_ENV=production`) by default. This is a safety measure.

When you're ready to use it in production, add `allowProduction: true`:

```typescript
export const POST = createHandler({
  adapter: prismaAdapter(prisma, { scopeField: 'organizationId' }),
  sharedSecret: process.env.AUTONOMA_SHARED_SECRET!,
  signingSecret: process.env.AUTONOMA_SIGNING_SECRET!,
  allowProduction: true,  // ← enable in production
  auth: async (user) => { /* ... */ },
})
```

## 8. Connect to Autonoma

Deploy your endpoint and paste `AUTONOMA_SHARED_SECRET` into the Autonoma dashboard when connecting your app. The platform will:

1. Call `discover` to learn your schema
2. Generate scenario data based on your models
3. Send that data in `up` requests before each test
4. Send `down` requests after each test to clean up
